# FINESSSIM Dental Studio

Сайт и CRM стоматологической студии. Репозиторий подключён к Cloudflare Pages.

## Архитектура

- **Cloudflare Pages** — публичный сайт и панель владельца.
- **Cloudflare Pages Functions** — API в `functions/api/[[path]].js`.
- **Cloudflare D1** — база CRM, подключённая к Function binding с именем `DB`.
- **GitHub `main`** — исходный код и история изменений.

Публичный адрес проекта: https://finesssim777.pages.dev/

## Настройки Cloudflare

Проверьте, что у Pages-проекта настроены:

### D1 binding

| Поле | Значение |
|---|---|
| Variable name | `DB` |
| Database | `finesssim-db` |

### Secrets

В настройках Pages → Settings → Variables and Secrets должны быть заданы секреты:

- `ADMIN_PASSWORD` — пароль владельца.
- `SESSION_SECRET` — случайный длинный секрет для подписи сессий и хеширования IP.
- `TELEGRAM_BOT_TOKEN` — токен Telegram-бота.
- `TELEGRAM_CHAT_ID` — ID чата для уведомлений.

Значения секретов нельзя добавлять в GitHub, исходный код, README, переписку или публичные документы. При компрометации секрет нужно заменить в Cloudflare и проверить связанные интеграции.

## Панель владельца

Откройте:

https://finesssim777.pages.dev/admin.html

Владелец может управлять:

- текстами и контактными данными сайта;
- услугами, ценами и продолжительностью приёма;
- сотрудниками и их расписанием;
- входящими и созданными вручную записями;
- статусами записей;
- доходами, расходами и отчётами;
- журналом действий;
- резервными копиями базы.

Доступ к панели защищён паролем и подписанной сессионной cookie. Для входа нужны настроенные `ADMIN_PASSWORD` и `SESSION_SECRET`.

## Резервное копирование

1. Войдите в панель владельца.
2. Откройте раздел финансов и блок резервной копии.
3. Нажмите «Скачать backup JSON».
4. Сохраните файл в защищённом месте с ограниченным доступом.
5. Делайте новую копию после важных изменений и регулярно по внутреннему графику клиники.

Резервная копия содержит персональные данные пациентов и финансовую информацию. Не отправляйте её в открытые чаты и не храните в общедоступных папках.

### Восстановление

Восстановление полностью заменяет данные бизнес-таблиц содержимым выбранной копии. Перед восстановлением обязательно скачайте текущую копию. Сначала проверяйте процедуру на отдельной тестовой базе D1. Не проверяйте восстановление на рабочей базе клиники.

## Проверка перед передачей владельцу

- [ ] В Cloudflare настроен binding `DB` к правильной D1.
- [ ] Все четыре секрета заданы и не раскрыты.
- [ ] Владелец может войти и выйти из панели.
- [ ] Публичная форма создаёт запись.
- [ ] Недоступные и занятые интервалы не предлагаются.
- [ ] Проверены рабочие дни, часы и продолжительность каждой услуги.
- [ ] Владелец может создать, изменить и отменить запись.
- [ ] При завершении записи доход отражается корректно; при отмене завершённой записи выполняется сторно.
- [ ] Проверены создание, изменение, удаление и восстановление расхода.
- [ ] JSON-резервная копия скачивается и проходит проверку восстановления на отдельной тестовой базе.
- [ ] Уведомления Telegram проверены на тестовой записи.
- [ ] На сайте размещены утверждённые документы по персональным данным и согласию.

## Важные ограничения перед использованием с реальными пациентами

Файл `privacy.html` пока является **проектом**, а не утверждённой политикой. В нём остаются незаполненные юридические сведения и вопросы о целях, основаниях, сроках и фактических местах обработки данных.

API отправляет уведомление в Telegram с данными записи (имя, телефон, услуга, специалист, дата, время и комментарий). Этот отдельный поток данных нужно описать и проверить до использования с реальными пациентами.

Выбор Cloudflare как платформы не является подтверждением соответствия требованиям законодательства о персональных данных. До загрузки реальных данных пациентов оператору клиники необходимо проверить применимые требования, фактическое размещение данных и передачу данных подрядчикам с ответственным специалистом/юристом.

## Изменения и эксплуатация

- Изменения в `main` запускают деплой через подключённый Cloudflare Pages проект.
- После каждого изменения проверяйте статус деплоя в Cloudflare.
- После обновлений проверяйте вход владельца, форму записи и ключевые разделы CRM.
- Не меняйте структуру D1 вручную без резервной копии и проверенного плана миграции.
- Бесплатные лимиты и условия Cloudflare могут меняться. Для стабильной работы контролируйте использование ресурсов и ошибки в логах.
